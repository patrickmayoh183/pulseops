# PulseOps 立项与交付范围

状态：立项已确定，实现与部署验收进行中。本文中的验收目标不代表已经通过。

## 1. 要解决的问题

个人开发者部署网站后，通常需要回答三个问题：服务最近是否正常、异常从什么时候开始、处理过程中发生了什么。仅查看服务器是否启动或偶尔打开网页，很难形成连续记录。

PulseOps 将周期 HTTPS 检查、结果历史、故障状态变化和公开进展汇总到一个可访问的产品中。开发者能够维护自己的服务，也能够向访问者展示当前状态和故障处理过程。

项目使用用户已有的一台阿里云 ECS、MySQL RDS 和备案域名 `ldjava.com`。后端使用 Java，前端使用 Vue；不依赖付费外部 API。

## 2. 方案筛选

| 候选 | 真实用途 | 能展示的技术 | 本次取舍 |
|---|---|---|---|
| 服务巡检与故障状态页 | 持续观察自己的站点和 API | 调度、并发控制、状态机、查询聚合、安全限制 | 采用；完整闭环短，运行数据可核验 |
| Webhook 可靠投递平台 | 接收、签名转发、重试和重放事件 | 幂等、退避、投递状态机、事务一致性 | 需要更多真实业务方接入才能展示用途 |
| 小团队工单与处理时限工作台 | 需求、故障和处理记录流转 | 权限、工作流、操作审计 | 更依赖多人使用，容易停留在表单管理 |

选型依据是能否在现有资源内完整交付并持续使用，而不是堆叠中间件数量。

## 3. 用户与使用路径

**访客**打开公开状态页，查看当前服务状态、最近检查和故障公告；无需账户。

**管理员**登录后配置已经授权的监控目标，选择期望状态码与检查间隔。发现故障后，在故障记录中添加处理说明，恢复后保留完整时间线。

**系统调度器**领取到期任务、执行受限检查、记录结果，并依据连续失败或成功次数推进故障状态。系统不通过开放注册接受匿名 URL。

## 4. MVP 功能边界

| 范围 | 交付要求 |
|---|---|
| 公开状态 | 总体状态、服务状态、最后检查时间、样本统计、故障时间线 |
| 单服务详情 | 最近 100 条检查、探测耗时（包含失败探测）、结果或错误分类 |
| 管理员认证 | HttpOnly 会话 Cookie、登录/退出、写请求 CSRF 校验 |
| 监控管理 | 新建、编辑、启停、立即检查；不提供删除接口 |
| 检查策略 | HTTPS 443 GET、预期状态码、超时、最短 30 秒间隔 |
| 故障判断 | 两次连续失败打开；两次连续成功恢复 |
| 故障沟通 | 管理员添加公开进展备注 |
| 操作审计 | 保留管理操作的操作者、资源、时间和摘要 |
| 运维能力 | 配置外置、数据库迁移、健康检查、数据保留策略 |

初始化仅允许使用显式配置的真实监控目标；未配置时展示空状态。演示数据、压力测试结果和生产测量不能混在一起。

本次不包含多租户、自助注册、多地域探测、短信、收费订阅、复杂告警路由或分布式部署。未来扩展应以实际使用需求为依据。

## 5. 可展示的技术问题

1. **任务为什么不会同时重复执行？**说明数据库任务领取与 lease 的边界、进程重启后的恢复方式，以及立即检查与周期任务如何协调。
2. **为什么一次失败不直接报故障？**用连续两次失败/成功的状态机解释误报、检测延迟和恢复延迟之间的取舍。
3. **为什么不能允许任意 URL？**说明云环境中的 SSRF、白名单、地址校验和重定向限制。
4. **数据越来越多怎么办？**说明按监控与时间检索的索引、结果保留策略，以及什么时候才需要聚合表或分区。
5. **如何证明系统运行过？**提供域名、真实检查记录、故障演练记录和部署验收证据。

## 6. 交付阶段与完成标准

| 阶段 | 产出 | 完成条件 |
|---|---|---|
| 立项与设计 | 产品边界、接口合同、架构说明 | 前后端对字段、状态和错误处理形成一致约定 |
| 实现 | 后端、前端、迁移脚本、测试 | 可构建，核心业务与权限测试通过 |
| 集成 | 可操作的完整产品 | 管理员配置能触发真实检查，公开页读取真实结果 |
| 部署 | ECS 运行服务、RDS 数据、域名入口 | 公网连通，密钥不入库，进程可管理 |
| 验收 | 构建/测试记录与线上验证记录 | 关键用例通过，限制如实记录 |
| 简历交付 | README、架构与面试说明 | 每一项能力都有可指向的代码或运行证据 |

本次上线成功的标准是可访问、可管理、可检查、可追溯并可重启恢复。未经验证的吞吐量、可用性和高并发能力不作为成果。

## 7. 已知边界

检查成功率计算的是已完成样本中的成功比例，不等同于按时间计量的 SLA。计划检查因进程停机而缺失时，不能用成功样本掩盖这个空白。

探测器与被展示的平台共用一台 ECS，主机故障、网络中断或 Java 进程退出时，探测器自身也可能不可用。这种部署适合服务巡检和故障过程管理，不能替代独立的外部监控点。
